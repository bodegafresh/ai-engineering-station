# v0.3 — First real local model response

This release intentionally does **not** edit repository files. The model produces text only.

## Design
- SQLite is authoritative for task state and model output.
- A single blocking Vert.x worker executes one model request at a time.
- The event loop is never blocked by model HTTP or JDBC.
- Model execution is **disabled by default**; disabled tasks remain PENDING.
- A successful task requires nonempty model output persisted in the same transaction as COMPLETED.
- Task results are available through GET `/api/v1/tasks/{id}/result`.
- A model request error produces FAILED, never fake success.
- This POC is single-node. Timeout < lease, and stale completions are fenced.

## Limitations / next release
- No automatic retries for model failures yet (FAILED is terminal); retry policy will be separate.
- No lease heartbeat for long-running tools; requests are bounded by HTTP timeout.
- No prompt injection defense for untrusted repository contents yet; do not provide secrets.
- No code execution or filesystem writes by the model.
- No streaming yet. Output may be truncated by the local model server configuration.
- API binds to loopback; authentication must be added before exposing beyond localhost.
- This is a POC, not a full multi-agent workflow.

## Test strategy
- Unit tests for result persistence, fencing and a local mock HTTP model.
- `./gradlew clean test` and `./gradlew build`.
- Manual: start model, enable flag, POST, poll GET, fetch `/result`.
- Restart Quarkus and verify persisted output remains available.
