# v0.2 — Orquestador durable (incremento inicial)

## Alcance

- Compatibilidad con la base existente: las columnas nuevas se añaden sin borrar tareas.
- Persistencia SQLite WAL y outbox transaccional para transiciones.
- Claim atómico de tareas PENDING, lease y recuperación de RUNNING vencidos.
- Reintentos con límite y backoff; cancelación de tareas PENDING.
- Vert.x Event Bus como notificación interna, no como cola durable.
- El procesador actual es **simulado**: marca tareas completadas sin ejecutar IA.

## Límites explícitos

- Un único proceso Quarkus sobre SQLite local. No está diseñado para ejecución distribuida.
- El lease **no tiene heartbeat**. No ejecutar herramientas que duren más que el lease hasta implementar renovación y fencing tokens.
- La publicación al Event Bus es at-least-once; consumidores deben ser idempotentes.
- `task.events` es telemetría interna no durable. La confirmación del outbox significa que se publicó localmente, no que otro servicio lo procesó.
- El procesador simulado **no valida criterios de aceptación**. No confundir `COMPLETED` con trabajo de ingeniería real.
- Migraciones automáticas por columnas son solo transición desde v0.1; adoptar Flyway/Liquibase antes de crecer el esquema.
